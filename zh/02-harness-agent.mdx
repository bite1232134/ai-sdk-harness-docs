# HarnessAgent

`HarnessAgent` 是 AI SDK `Agent` 的一个实现，由 harness（智能体运行框架）适配器提供支撑。
它提供 `generate()` 和 `stream()` 方法，返回与 AI SDK 兼容的结果，
而这些结果由一个预先配置好的 harness 驱动。

## 安装

安装核心 harness 包、一个 harness 适配器和一个沙箱适配器：

<InstallPackages packages="@ai-sdk/harness @ai-sdk/harness-claude-code @ai-sdk/sandbox-vercel" />

像 Claude Code 和 Codex 这类由 bridge 支撑的 harness，需要使用真实的网络沙箱，
例如 `@ai-sdk/sandbox-vercel`。像 Pi 这类宿主运行时 harness 也可以配合
`@ai-sdk/sandbox-just-bash` 运行，因为它们不需要沙箱对外暴露端口。

## 创建智能体

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { claudeCode } from '@ai-sdk/harness-claude-code';

export const agent = new HarnessAgent({
  harness: claudeCode,
  model: 'claude-sonnet-4-6',
  instructions:
    'You are a careful coding assistant. Prefer small changes and explain tradeoffs.',
});
```

请在模块作用域内构造智能体。它保存的是配置，而不是一个活跃会话。
活跃状态属于 `HarnessAgentSession`。
单独创建一个沙箱会话，并将其传给 `agent.createSession()`：

```ts
import { createVercelNetworkSandboxSession } from '@ai-sdk/sandbox-vercel';

const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  ports: [4000],
  template: await agent.getSandboxTemplate(),
});
```

通过设置 `model` 来选择 harness 运行时使用的模型。模型标识符
因 harness 而异。省略时，harness 使用其默认模型。
模型是按回合应用的，因此 `prepareCall` 可以在回合之间替换它。

要使用这个智能体，请确保已设置带有沙箱和 harness 凭据的环境变量。

## 运行一个回合

```ts
const session = await agent.createSession({ sandboxSession });

let exitCode = 0;
try {
  const result = await agent.generate({
    session,
    prompt: 'Create a short TODO.md for this repository.',
  });

  console.log(result.text);
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  await sandboxSession.destroy();
  process.exit(exitCode);
}
```

`generate()` 会耗尽该回合并返回一个 `GenerateTextResult`。

使用 `stream()` 获得增量输出：

```ts
const session = await agent.createSession({ sandboxSession });

let exitCode = 0;
try {
  const result = await agent.stream({
    session,
    prompt: 'Create a short TODO.md for this repository.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} catch (err) {
  exitCode = 1;
  console.error(err);
} finally {
  await session.destroy();
  await sandboxSession.destroy();
  process.exit(exitCode);
}
```

## 生命周期回调

在 `HarnessAgent` 上配置生命周期回调，以观测智能体调用、模型
步骤和工具执行：

```ts
const agent = new HarnessAgent({
  harness: claudeCode,
  tools: { weather },
  onStart: event => console.log('call started', event.callId),
  onStepStart: event => console.log('step started', event.stepNumber),
  onLanguageModelCallStart: event =>
    console.log('model call started', event.modelId),
  onLanguageModelCallEnd: event =>
    console.log('model call ended', event.finishReason),
  onToolExecutionStart: event =>
    console.log('tool started', event.toolCall.toolName),
  onToolExecutionEnd: event => console.log('tool ended', event.toolOutput.type),
  onStepEnd: step => console.log('step ended', step.stepNumber),
  onEnd: event => console.log('call ended', event.finishReason),
});
```

在单次 `generate()` 和 `stream()` 调用上配置的回调会
在设置级回调之外被额外调用，其中设置级回调先被调用。
回调错误会被忽略，不会改变智能体的执行。

Harness 运行时会内部执行其内置工具。对于这些工具，
`onToolExecutionStart` 和 `onToolExecutionEnd` 描述的是运行时报告结果之后的逻辑工具
生命周期。这些回调仍然会在工具结果发布到结果流之前交付。

## 运行时上下文

在 `HarnessAgent` 上设置 `runtimeContext`，使应用上下文可用于
每一个回合。使用 `prepareCall` 为每个新的提示回合替换它。已准备的
上下文可通过 `generate()` 和 `stream()` 获取，并且在使用
`continueGenerate()` 和 `continueStream()` 进行内存中续接期间保持不变。
生命周期回调会收到完整上下文，它也可以通过每个结果的
`finalStep.runtimeContext` 获取。

```ts
const agent = new HarnessAgent({
  harness: claudeCode,
  runtimeContext: {
    conversationId: 'conversation-123',
    userId: 'user-456',
  },
  telemetry: {
    includeRuntimeContext: {
      conversationId: true,
    },
  },
  onEnd: ({ runtimeContext }) => {
    console.log(runtimeContext.userId);
  },
});
```

运行时上下文默认不会进入遥测。使用
`telemetry.includeRuntimeContext` 来把单个顶层属性加入允许列表；
只有被设置为 `true` 的属性才会发送给遥测集成。生命周期
回调和结果仍然会收到完整上下文，因此请避免存放那些
使用方不应访问的机密信息。

## 生成结构化输出

在构造 `HarnessAgent` 时设置 `output`，以要求每个回合都产生相同类型的输出。
智能体会把输出规范转换为 JSON Schema 交给 harness 适配器，
校验完成后的响应，并通过 `result.output` 返回解析后的值。

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { Output } from 'ai';
import { z } from 'zod';

const agent = new HarnessAgent({
  harness: claudeCode,
  output: Output.object({
    schema: z.object({
      recipe: z.object({
        name: z.string(),
        ingredients: z.array(
          z.object({
            name: z.string(),
            amount: z.number(),
            unit: z.enum(['oz', 'fl oz', 'cup', 'gallon']),
          }),
        ),
        steps: z.array(z.string()),
      }),
    }),
  }),
});

const session = await agent.createSession({ sandboxSession });
try {
  const result = await agent.generate({
    session,
    prompt: 'Generate a lasagna recipe.',
  });
  console.dir(result.output, { depth: Infinity });
} finally {
  await session.destroy();
}
```

使用 `stream()` 时，读取 `partialOutputStream` 获取增量解析的值，
并 await `result.output` 获取校验后的最终值。结构化数据也仍然
以 JSON 形式出现在常规文本和流式表面上；适配器不会把它
加入 `finish` 部分。

Harness 结构化输出需要一个 schema。无 schema 的 `Output.json()` 以及
无法强制实施该 schema 的适配器或运行时配置会抛出
`HarnessCapabilityUnsupportedError`；参见
[适配器能力表](/zh/05-harness-adapters)。

## 消息与历史

harness 会话拥有其原生对话历史。当你传入 `messages`
或消息数组形式的 `prompt` 时，`HarnessAgent` 会把最新的用户消息作为
该回合的新输入。它不会把完整的先前对话重新回放给
harness。

末尾的 tool 消息处理方式不同：工具审批响应和
客户端提供的工具结果会续接产生
相应请求或工具调用的那个未完成 harness 回合。

这与模型调用不同，在模型调用中应用通常会发送完整的
消息历史。在聊天路由中，请持久化并恢复 harness 会话，
而不是依赖消息回放。

### 读取运行时自身的历史

运行时的对话可能在你的进程之外增长——例如同一个
对话在该智能体自己的 CLI 中交互式地继续——
而实时事件流永远看不到这些交流。能够访问
其运行时存储的适配器通过 `session.readHistory()` 暴露它们：

```ts
const { messages, cursor } = await session.readHistory();
// Messages use role/content shapes. Adapter-specific details, including the
// runtime's raw record, are available under harnessMetadata.

// Later: read only what was recorded since.
const delta = await session.readHistory({ since: cursor });
```

历史读取是适配器特定的；在调用此方法之前请先查看适配器能力表。
当适配器未实现历史读取时，`readHistory()` 抛出 `HarnessCapabilityUnsupportedError`；
当适配器实现了但在当前环境中无法访问运行时的
存储时（例如存储位于远程沙箱内），它抛出 `HarnessHistoryUnavailableError`。
尚无任何已记录消息的对话不算错误；它会解析为空 `messages` 数组。

## 会话生命周期

要显式结束每个会话：

- `session.destroy()` 停止运行时并舍弃可恢复性。
- `session.detach()` 停放运行时，返回恢复状态，并让所提供的沙箱
  继续运行以便之后重新接入。如果该回合未完成，
  恢复状态会包含续接状态。
- `session.stop()` 保存恢复状态，然后停止运行时。如果
  该回合未完成，恢复状态会包含续接状态。
- `session.suspendTurn()` 用于跨越
  进程边界的高级活跃回合续接。
- `session.hasUnfinishedTurn()` 报告当前回合是否必须在
  会话接受新提示之前被续接或挂起。

一次性脚本和测试请使用 `destroy()`。需要多回合连续性的
HTTP 路由请使用 `detach()` 或 `stop()`。

## 在回合之间更改设置

使用 `callOptionsSchema` 和 `prepareCall` 为每个新回合派生 `model`、`skills`、
`instructions`、`tools` 和 `runtimeContext`。这遵循与 `ToolLoopAgent`
相同的调用选项模式：

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { tool } from 'ai';
import { z } from 'zod';

const getPolicy = tool({
  description: 'Look up the active project policy.',
  inputSchema: z.object({}),
  execute: async () => 'Keep public APIs backward compatible.',
});

const agent = new HarnessAgent({
  harness: claudeCode,
  tools: { getPolicy },
  callOptionsSchema: z.object({
    area: z.enum(['frontend', 'backend']),
    enablePolicyTool: z.boolean(),
    useCheaperModel: z.boolean(),
  }),
  prepareCall: ({ options, ...call }) => ({
    ...call,
    model: options.useCheaperModel ? 'claude-haiku-4-5' : undefined,
    instructions: `Work as the ${options.area} specialist.`,
    runtimeContext: { area: options.area },
    skills: [options.area === 'frontend' ? frontendSkill : backendSkill],
    tools: options.enablePolicyTool ? { getPolicy } : undefined,
  }),
});

const session = await agent.createSession({ sandboxSession });
try {
  await agent.generate({
    session,
    prompt: 'Review the current implementation.',
    options: {
      area: 'frontend',
      enablePolicyTool: false,
      useCheaperModel: false,
    },
  });

  await agent.generate({
    session,
    prompt: 'Now review the API contract.',
    options: {
      area: 'backend',
      enablePolicyTool: true,
      useCheaperModel: true,
    },
  });
} finally {
  await session.destroy();
}
```

`prepareCall` 会在新的提示的自定义 `options` 通过校验之后运行。
之后它的设置在整个该回合内固定不变。如果该回合因
工具结果、审批、停止条件或进程交接而暂停，其
续接会复用相同的设置，不会再次调用 `prepareCall`。
这样可以防止设置在回合中途发生变化。

更改 `model` 不会创建新的 harness 会话。每个适配器会在
下一个提示之前切换或重新配置其运行时，同时保留该会话的
对话历史。

当 Codex 适配器的技能、instructions 或工具目录发生变化时，
它会启动一个全新的原生 Codex 线程，因为 `codex exec resume` 会保留
最初的原生线程引导启动状态。harness 会话仍然可用，但先前的
原生对话上下文不会跨越这个设置变更边界。设置未发生变化的
回合会继续使用现有的原生线程。

请把 `abortSignal` 直接传给 `generate()` 或 `stream()`；它本身已经是一个
按调用生效的设置，不属于 `prepareCall`。`output` 也固定在
智能体上，因为其响应格式与智能体的输出 schema 绑定。

当你把 `sandboxSession` 传给 `agent.createSession()` 时，调用方保留
对该沙箱的所有权。`session.stop()` 和 `session.destroy()` 仍会结束
harness 运行时，但不会停止或销毁所提供的沙箱会话。
在这种情况下，智能体不需要在其构造函数中提供 `sandbox` 提供方。

```ts
const session = await agent.createSession({
  sessionId: chatId,
  sandboxSession,
});

try {
  const result = await agent.stream({ session, messages });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }

  const resumeState = await session.detach();
  await persistResumeState({ chatId, resumeState });
} catch (error) {
  await session.destroy();
  throw error;
}
```

## 恢复

请持久化这个不透明的恢复状态。在本示例中，harness 的 `sessionId` 就是
`chatId`，而沙箱 ID 由同一个已知 ID 推导而来。如果你的
应用无法推导出沙箱 ID，请改为把 `sandboxSession.id` 与
harness 的 `sessionId` 和恢复状态一起持久化。在要求智能体恢复之前
先重新接入沙箱。当你在创建时指定 `sandboxId`，它命名的是一个**新的**
活跃沙箱，绝不会去查找已有沙箱。与创建函数一起复用该 ID 会在
所命名的沙箱已存在时失败；只有恢复函数会执行查找。

```ts
const resumeState = await loadResumeState({ chatId });
const sandboxId = `chat-${chatId}`;

const sandboxSession = resumeState
  ? await resumeVercelNetworkSandboxSession({ sandboxId })
  : await createVercelNetworkSandboxSession({
      sandboxId,
      ports: [4000],
      template: await agent.getSandboxTemplate(),
    });

const session = await agent.createSession(
  resumeState
    ? { sessionId: chatId, resumeFrom: resumeState, sandboxSession }
    : { sessionId: chatId, sandboxSession },
);
```

`HarnessAgent` 在把恢复状态交给运行时之前，会校验它是由同一个
harness 适配器产生的。如果恢复状态包含未完成的回合，请在发送
新提示之前调用 `continueStream()` 或 `continueGenerate()`。Vercel 的恢复函数
会在沙箱于 `detach()` 之后仍在运行、或已停止但存有可恢复快照时
重新接入它。一旦 `sandboxSession.destroy()` 将其删除，该 ID 就无法再恢复。

## 续接已挂起的回合

对于必须跨进程边界交接活跃回合的高级工作流，
请挂起该回合并持久化续接状态：

```ts
if (session.hasUnfinishedTurn()) {
  const continuationState = await session.suspendTurn();
  await persistContinuationState({ chatId, continuationState });
}
```

当你只有来自 `suspendTurn()` 的原始续接状态时，请用
`continueFrom` 恢复，然后在不发送新提示的情况下续接该回合：

```ts
const session = await agent.createSession({
  sessionId: chatId,
  continueFrom: continuationState,
  sandboxSession,
  // Rebind this when the suspended turn used host-only tool context:
  toolsContext,
  runtimeContext,
});

const result = await agent.continueStream({ session });
```

使用 `continueStream()` 获得增量输出，或使用 `continueGenerate()` 耗尽
被续接的回合并返回一个 `GenerateTextResult`。

`toolsContext` 和 `runtimeContext` 有意不存储在
续接状态中，因为它们可能包含凭据或不可序列化的
宿主对象。当被挂起的回合使用了由 `prepareCall` 派生的上下文时，
请把相同的值传给 `createSession`，以便在续接该回合的进程中重新绑定它们。
在未重新绑定的情况下恢复进程后，续接
会使用智能体构造函数级别的 `runtimeContext` 和 `toolsContext`。

## 在一个 harness 步骤之后停止

使用 `stopWhen` 选择启用语义步骤边界。谓词会在真实的
harness 工具步骤之后运行，这些步骤可能继续进入另一个模型步骤，谓词会收到
当前调用中已完成的步骤。当某个谓词匹配时，
返回的结果会结束，而底层回合仍保持未完成。一个
终止性的纯文本步骤则会消费该回合的 `finish` 事件并自然结束。

```ts
import { isStepCount } from 'ai';

const steppedAgent = new HarnessAgent({
  harness: claudeCode,
  stopWhen: isStepCount(1),
});

const session = await steppedAgent.createSession({ sandboxSession });
const result = await steppedAgent.generate({
  session,
  prompt: 'Create a short TODO.md for this repository.',
});

if (session.hasUnfinishedTurn()) {
  const continueFrom = await session.suspendTurn();
  await persistContinuationState({ chatId, continuationState: continueFrom });
}
```

`stopWhen` 没有默认值。省略时，`HarnessAgent` 会持续运行直到
该回合自然结束或因等待宿主输入而暂停，从而保留
没有步骤控制的智能体的行为。请传入一个谓词或一个数组；
匹配任意谓词都会结束当前的结果片段。使用
`createSession({ continueFrom })` 和 `continueStream()` 或
`continueGenerate()` 来恢复被停止的回合。

## 准备沙箱

在 harness 启动之前，使用 `sandboxConfig` 准备沙箱。

`sandboxConfig.onBootstrap` 在沙箱模板创建期间运行，时机是在
harness 适配器自身的引导启动之后、且在支持快照的提供方发布
快照之前。请把它用于应当被未来会话复用的开销较大的设置。
当你提供 `onBootstrap` 时，也要提供 `bootstrapHash`；每当引导启动输出
应当使可复用快照失效时，就更改该哈希值。

`sandboxConfig.onSession` 在每次获取沙箱会话且其
工作目录存在之后运行，恢复的会话也包括在内。请把它用于按会话
创建文件或轻量级配置。

```ts
const agent = new HarnessAgent({
  harness: claudeCode,
  sandboxConfig: {
    workDir: 'repo',
    bootstrapHash: 'ripgrep-v1',
    onBootstrap: async ({ session, abortSignal }) => {
      const result = await session.run({
        command:
          'command -v rg >/dev/null || (apt-get update && apt-get install -y ripgrep)',
        abortSignal,
      });
      if (result.exitCode !== 0) {
        throw new Error(`Failed to install ripgrep: ${result.stderr}`);
      }
    },
    onSession: async ({ session, sessionWorkDir, abortSignal }) => {
      await session.writeTextFile({
        path: `${sessionWorkDir}/README.md`,
        content: 'Session notes for the harness.',
        abortSignal,
      });
    },
  },
});
```

`workDir` 是可选的。提供时，它必须相对于沙箱的
默认工作目录，并被用作会话工作目录。把它设为
`'.'` 以直接使用沙箱的默认工作目录。省略时，
常规会话使用默认的 `<harnessId>-<sessionId>` 目录，而
`onBootstrap` 会收到沙箱的默认工作目录。

## 准备可复用的沙箱

在创建沙箱之前，使用 `agent.getSandboxTemplate()` 解析某个 harness 的引导启动配方
和 `sandboxConfig.onBootstrap`。模板的身份
在沙箱创建之前就已确定。Vercel 会持久化已准备的快照，并
基于它创建活跃沙箱；相同的调用会复用该快照：

```ts
const sandboxSession = await createVercelNetworkSandboxSession({
  runtime: 'node24',
  ports: [4000],
  template: await agent.getSandboxTemplate(),
});

const session = await agent.createSession({ sandboxSession });
try {
  await agent.generate({ session, prompt: 'Inspect this repository.' });
} finally {
  await session.destroy();
  await sandboxSession.destroy();
}
```

对于共享同一个调用方引导启动钩子的多个 harness，请基于
所有适配器构建一个模板。重复的 `harnessId` 值以最后一个适配器为准，
配方身份在计算哈希之前会先排序。`onSession` 不属于
模板，它会在每个已获取的会话上单独运行。

```ts
import { createHarnessSandboxTemplate } from '@ai-sdk/harness/agent';

const template = await createHarnessSandboxTemplate({
  harnesses: [claudeCode, codex],
  sandboxConfig,
});
console.log(template?.identity);

const sandboxSession = await createVercelNetworkSandboxSession({
  source: { type: 'snapshot', snapshotId: baseSnapshotId },
  ports: [4000],
  template,
});
```

派生出的模板会把源快照 ID 纳入其缓存键，因此
以相同来源和模板重复调用会复用已准备的快照。在依赖
缓存模板时，请固定可变的 Git 修订版本、镜像标签和源 URL。
`sandboxId` 命名的是活跃沙箱，而不是其可复用模板。
现有的原生 `name` 选项仍然用于命名活跃沙箱；如果两者都被
提供，它们的值必须一致。

## 设置

`HarnessAgent` 接受以下主要设置：

- `harness`：适配器实例。
- `model`：可选的 harness 特定模型标识符。省略时，
  harness 使用其默认模型。
- `id`：可选的稳定智能体标识符。
- `instructions`：在支持时追加到运行时的系统或开发者
  提示之后的指令，否则前置到用户提示。
- `headers`：随模型请求发送的额外请求头。请求头在
  构造时即固定。不允许使用 `authorization`、`x-api-key`、`user-agent` 和
  `x-client-app`。
- `callOptionsSchema` 和 `prepareCall`：校验自定义调用选项并为每个新回合派生
  model、skills、instructions 和 tools。
- `output`：应用于每个回合的类型化输出规范。
- `stopWhen`：在一个已完成的、可继续进入另一个模型步骤的
  harness 工具步骤之后结束结果片段的条件。
- `tools`：harness 调用时由宿主执行的 AI SDK 工具。
- `runtimeContext`：每个回合转发给生命周期回调和
  结果的应用上下文；`prepareCall` 可以为新的提示回合替换它。
- `activeTools`：harness 可以调用的内置工具和宿主执行工具的
  允许列表。
- `inactiveTools`：harness 不能调用的内置工具和宿主执行工具的
  拒绝列表。
- `skills`：由适配器呈现的指令包。
- `permissionMode`：内置工具权限模式。
- `toolApproval`：宿主执行工具的审批状态映射。
- `sandboxConfig`：沙箱工作目录和生命周期钩子配置。
- `telemetry`、`debug` 和 `onLog`：可观测性与诊断。使用
  `telemetry.includeRuntimeContext` 把运行时上下文属性加入遥测的
  允许列表。

遥测会报告每个回合解析后的模型、instructions 和活跃的
宿主定义工具。技能属于适配器上下文，没有对应的
AI SDK 遥测字段，因此不会包含在标准遥测事件中。

适配器特定的设置应放在适配器工厂上，例如
`createCodex({ reasoningEffort: 'high' })`。

## 自定义沙箱编排

当你的应用自行创建和管理沙箱时，请先准备网络
沙箱会话，然后把同一个会话传给 `agent.createSession()`。
智能体不会创建沙箱，也不会停止或销毁
调用方拥有的沙箱。

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { claudeCode } from '@ai-sdk/harness-claude-code';
import { createVercelNetworkSandboxSessionFromNativeSandbox } from '@ai-sdk/sandbox-vercel';
import { Sandbox } from '@vercel/sandbox';

const sandbox = await Sandbox.create({
  runtime: 'node24',
  ports: [4000],
});
const sandboxSession =
  createVercelNetworkSandboxSessionFromNativeSandbox(sandbox);

const agent = new HarnessAgent({ harness: claudeCode });
const session = await agent.createSession({ sandboxSession });

try {
  const result = await agent.stream({
    session,
    prompt: 'Create a short TODO.md for this repository.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} finally {
  await session.destroy();
  await sandboxSession.destroy();
}
```

### 无网络控制的基础沙箱会话

以下示例演示基础会话 API 的工作方式。如果你的
项目能够暴露完整的网络沙箱会话，强烈建议传入该会话。
只有当你的项目无法暴露完整网络会话时，才传入受限的基础会话。

基础沙箱会话只暴露文件系统和进程 API。智能体
仍然把沙箱生命周期留给调用方。对于由 bridge 支撑的 harness，
请在适配器上配置 bridge 端口及其外部可达端点，
因为基础会话无法解析它们。

```ts
import { HarnessAgent } from '@ai-sdk/harness/agent';
import { createClaudeCode } from '@ai-sdk/harness-claude-code';
import {
  createVercelNetworkSandboxSessionFromNativeSandbox,
  createVercelSandboxSessionFromNativeSandbox,
} from '@ai-sdk/sandbox-vercel';
import { Sandbox } from '@vercel/sandbox';

const sandbox = await Sandbox.create({
  runtime: 'node24',
  ports: [4000],
});
const sandboxSession =
  createVercelNetworkSandboxSessionFromNativeSandbox(sandbox);
const portEndpoint = await sandboxSession.getPortEndpoint({
  port: 4000,
  protocol: 'ws',
});
const restrictedSandboxSession =
  createVercelSandboxSessionFromNativeSandbox(sandbox);
const claudeCode = createClaudeCode({ port: 4000, portEndpoint });

const agent = new HarnessAgent({ harness: claudeCode });
const session = await agent.createSession({
  sandboxSession: restrictedSandboxSession,
});

try {
  const result = await agent.stream({
    session,
    prompt: 'Create a short TODO.md for this repository.',
  });

  for await (const part of result.stream) {
    if (part.type === 'text-delta') {
      process.stdout.write(part.text);
    }
  }
} finally {
  await session.destroy();
  await sandboxSession.destroy();
}
```
